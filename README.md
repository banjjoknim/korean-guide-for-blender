# 블렌더 가이드 (한국어)

**하고 싶은 일을 한국어로 치면 블렌더 기능 이름과 단축키, 메뉴 위치를 알려 주는 팝업이다.**

블렌더를 처음 쓸 때 막히는 지점은 문법이 아니라 "이 기능의 영어 이름이 무엇인지 모른다"는 것이다.
그래서 블렌더가 원래 갖고 있는 검색(F3)으로는 찾을 수가 없다. 이 애드온은 그 자리를 메운다.

| 이렇게 치면 | 이것을 찾아 준다 |
|---|---|
| `면 나누기` | Subdivide · 우클릭 메뉴 · 에디트 모드 필요 |
| `둥글게` | Bevel · `⌘B` |
| `까맣게` | 면 방향 바로잡기 (Recalculate Normals) · `⇧N` |
| `안 골라져` | X-Ray 켜기 · `⌥Z` |
| `날아갔어` | 지난 작업 되살리기 (Recover Last Session) |
| `ㅁㄴㄴ` | 면 나누기 (초성으로도 찾는다) |
| `면을 둘로 나누고 싶어` | 면 잘게 나누기 (문장으로 쳐도 찾는다) |
| `물체를 움직이게 하고 싶어` | 움직임 기록하기 (키프레임) |
| `how do i bevel an edge` | 모서리 둥글게 깎기 (영어로도 찾는다) |
| `키프래임` | 움직임 기록하기 (오타도 잡는다) |
| `데이터 전송` | Data Transfer 모디파이어 (기능이 아닌 것도 찾는다) |

검색어를 치지 않으면 **지금 이 순간 쓸 수 있는 기능**이 나온다.
오브젝트 모드에서 열면 오브젝트 모드에서 되는 것이, 에디트 모드에서 열면 에디트 모드에서 되는 것이 나온다.

## 설치

### 블렌더 4.2 이상

[Releases](../../releases) 에서 `blender_guide_ko-*.zip` 을 받아 **블렌더 창에 그대로 떨군다.**
직접 만들려면 `./build_extension.sh` 를 돌리면 `dist/` 에 생긴다.

### 그 전 판, 또는 고쳐 가며 쓸 때

```bash
./install.sh
```

이 명령은 저장소의 애드온 폴더를 블렌더 애드온 자리에 **바로가기(심볼릭 링크)로 연결한다.**
복사하지 않기 때문에 저장소에서 파일을 고치면 블렌더 쪽에 바로 반영된다.
끊으려면 `./install.sh --remove` 를 친다.

연결한 뒤 블렌더에서 켠다. `Edit > Preferences > Add-ons` 에서 `가이드` 로 찾아 체크를 켠다.

## 쓰는 법

### 여는 방법 세 가지

| 방법 | 설명 |
|---|---|
| 맥은 `Cmd`+`Shift`+`H`, 그 밖은 `Ctrl`+`Shift`+`H` | 어디서나 팝업이 뜬다. 뜨자마자 바로 칠 수 있다 |
| 같은 조합에 `;` | **한글 입력 중에는 이것을 쓴다.** 아래를 보라 |
| `N` 키 > 가이드 탭 | 3D 화면 오른쪽에 늘 떠 있는 자리이다. 단축키를 잊었을 때 쓴다 |
| `Help` 메뉴 | 막혔을 때 가장 먼저 열어 보는 메뉴라서 여기에도 넣어 두었다 |

단축키가 다른 기능과 겹치면 애드온 설정 화면에서 바꿀 수 있다.
겹치는 기능이 있으면 그 화면이 빨간 글씨로 알려 준다.

### 단축키가 왜 두 개인가

**한글 입력 상태에서는 글자 글쇠를 단축키로 쓸 수 없다.** 블렌더가 받는 사건을 직접
기록해서 확인한 사실이다.

```
한글 상태에서 Cmd+Shift+H   →  type=''             ← 글쇠 종류가 비어 있다
글쇠를 뗄 때                →  unicode='ㅗ'        ← 자모로 바뀌어 있다
한글 상태에서 Cmd+Shift+;   →  type='SEMI_COLON'   ← 그대로 들어온다
```

한글 입력기가 `H` 를 `ㅗ` 로 바꿔서 넘기는데, 블렌더에는 자모에 해당하는 글쇠가 없다.
그래서 맞출 대상이 아예 없어진다. **수식키를 바꾸는 것으로는 해결되지 않는다.**
`Ctrl` 을 `Cmd` 로 바꿔 봐도 마찬가지였다.

반면 기호와 기능키는 자모로 바뀌지 않아 그대로 들어온다. 그래서 글자 글쇠 하나와
기호 글쇠 하나를 같이 등록한다. 영문으로 칠 때는 `H` 가 기억하기 쉽고, 한글로 칠
때는 `;` 가 언제나 듣는다.

세미콜론을 고른 까닭은 macOS 가 가로채지 않기 때문이다. `Cmd`+`Shift`+`/` 는 도움말,
`Cmd`+`Shift`+`4` 는 화면 찍기, ``Cmd``+`Shift`+`` ` `` 는 창 넘기기로 운영체제가 먼저
가져가서 블렌더까지 오지도 않았다.

### 화면에서 읽는 법

- 기능 이름이 **흐리게** 보이면 지금 모드에서는 쓸 수 없다는 뜻이다. 오른쪽에 빨간 글씨로
  까닭이 적히고, 그 옆의 `바꾸기` 를 누르면 쓸 수 있는 모드로 곧바로 넘어간다.
  목록에서 빼지 않고 흐리게만 두는 이유는, 없애 버리면 검색이 안 되는 것으로 오해하게 되고
  모드를 바꾸면 쓸 수 있다는 사실 자체를 배우지 못하기 때문이다.
  예전에는 `Tab 을 눌러 에디트 모드로` 라고만 적었는데, 고른 물체가 없거나 편집할 수 없는
  종류이면 Tab 을 눌러도 모드가 바뀌지 않는다. 그 상태에서는 `물체를 먼저 고르세요` 처럼
  바뀌지 않는 까닭을 대신 알려 준다.
- 단축키가 **괄호 안에** 있으면 손으로 적어 둔 예비 값이고, 괄호가 없으면 지금 이 블렌더에서
  직접 읽은 값이다. 단축키를 바꿔 쓴다면 괄호 없는 쪽이 실제 값이다.
  손으로 적어 둔 값은 맥 기준이라 `Ctrl+B` 가 아니라 `Cmd+B` 로 적혀 있다.
- 삼각형 화살표를 누르면 메뉴 위치와 주의할 점이 펼쳐진다.
- 별표를 누르면 즐겨찾기가 되어 맨 위에 모이고, 블렌더를 껐다 켜도 남는다.
- 한 번 골라 본 항목은 저절로 기억되어 **최근에 본 것**으로 맨 위에 모이고,
  다음에 검색할 때 위로 올라온다. 아래의 [검색 기록](#검색-기록)을 보라.

## 안내 모드

기능 이름만 알려 줘도 **그것이 화면 어디에 있는지** 모르면 결국 막힌다.
그래서 항목을 누르면 그 자리를 직접 짚어 주는 안내 모드를 기본으로 켜 둔다.

항목을 누르면 세 가지가 한꺼번에 일어난다.

1. 그 기능이 들어 있는 블렌더 메뉴가 **실제로 펼쳐진다.**
2. 그 메뉴가 있는 영역에 **주황색 테두리**가 둘러진다. 5초 뒤에 옅어지며 사라진다.
3. 펼친 설명에서 메뉴 경로가 `1. Edge > 2. Bevel Edges` 처럼 **단계별로** 끊겨 나온다.

**익숙해지면 끈다.** 팝업 위쪽의 `안내` 토글, 사이드바의 `안내 모드` 토글, 설정 화면 중
어디서 꺼도 된다. 끄면 이름과 단축키만 조용히 보여 준다.

세부 동작은 `Edit > Preferences > Add-ons` 의 설정 화면에서 따로 끌 수 있다.
메뉴만 펼치고 강조는 끄거나, 강조가 머무는 시간을 늘리는 식이다.

### 기능을 대신 실행해 주지는 않는다

이 애드온은 **무엇을 눌러야 하는지 알려 줄 뿐, 기능을 대신 실행하지 않는다.** 예전에는
`지금 실행` 단추가 있었지만 걷어냈다. 까닭은 바로 아래에 적어 두었다.

### 블렌더가 못 해 주는 것 (실행 단추를 걷어낸 까닭)

블렌더 파이썬 API 의 한계 때문에 할 수 없는 것이 있다. 나중에 다시 시도하지 않도록 적어 둔다.

- **마우스를 올리는 것만으로는 안내가 뜨지 않는다.** `UILayout` 에는 hover · highlight · focus
  라는 이름의 속성이 하나도 없어서, 레이아웃 요소에 마우스가 올라왔다는 사건을 받을 방법이 없다.
  게다가 팝업이 열려 있는 동안에는 모달 오퍼레이터도 이벤트를 받지 못한다. 그래서 클릭으로 대신한다.
- **펼친 메뉴 안에서 특정 줄만 강조하지는 못한다.** `bpy.ops.ui` 를 전부 훑어도 그런 기능이 없다.
  그래서 강조는 메뉴가 들어 있는 영역까지만 하고, 정확히 어느 줄인지는 경로 글자로 알려 준다.
- **화면 맨 위 막대에는 그림을 얹지 못한다.** `bpy.types` 에 `SpaceTopBar` 자체가 없어서
  그리기 손잡이를 걸 자리가 없다. `File` 과 `Edit` 메뉴는 위쪽 화살표가 붙은 쪽지로 가리킨다.
- 오른쪽 속성 패널 안의 아이콘처럼 메뉴가 아닌 자리는 펼칠 것이 없다. 이때는 패널 전체에
  테두리를 두르고 경로만 단계별로 보여 준다. 60개 항목 가운데 9개가 여기에 해당한다.
- **팝업 안에서 기능을 실행하면 반쪽으로 시작된다.** `invoke_popup` 으로 띄운 팝업은 단추를
  눌러도 닫히지 않는다. 그래서 돌리기처럼 마우스를 끄는 기능은 변형이 시작되더라도 팝업이
  그 위를 덮은 채로 남는다. 점선 안내선은 마우스까지 그어지는데 마우스가 팝업 위에 있으니
  가려지고, 팝업이 키 입력을 먼저 가져가므로 `X` · `Y` · `Z` 축 고정도 안 먹는다.
  블렌더에는 팝업을 닫는 API 가 아예 없다. `bpy.ops` 전체를 훑어도 없다.
  그래서 반쪽으로 시작되는 단추를 두느니 걷어내는 편이 낫다고 판단했다.
  단축키와 메뉴 위치는 그대로 보여 주고, 안내 모드에서는 실제 메뉴를 펼쳐 준다.
- **검색창에 커서가 들어가 있으면 팝업 안의 첫 클릭이 삼켜진다.** 그 클릭이 글자 입력 상태를
  빠져나오는 데 쓰이기 때문이다. 검색한 뒤 `Enter` 를 한 번 누르면 다음 클릭부터 바로 닿는다.

## 문장으로 찾기

낱말로 칠 줄 모르는 사람을 위해 **문장으로 쳐도 찾는다.**

```
'면을 둘로 나누고 싶어'          → 면 잘게 나누기
'물체를 움직이게 하고 싶어'      → 움직임 기록하기 (키프레임)
'움직임이 뚝뚝 끊겨'             → 보간 방식 바꾸기
'how do i bevel an edge'        → 모서리 둥글게 깎기
'how to play the animation'     → 움직여 보기 (재생)
```

**영어로도 찾는다.** 블렌더 자료는 대부분 영어라서 영어 이름을 어렴풋이 아는 사람이 많다.
`how do i`, `i want to` 같은 말은 걷어내고 `bevel`, `edge` 만 남긴다. `beveling` 처럼
어미가 붙어도 떼어 본다.

군더더기를 걷어내고 핵심 낱말만 남긴 뒤 원래 검색기에 넘긴다. 검색 규칙을 두 벌로
만들면 한쪽만 고쳐지므로 새 규칙을 만들지 않았다. 무엇으로 찾았는지
`이렇게 알아들었습니다: 면 · 둘 · 나누고` 처럼 보여 준다. 그래야 다음에는 더 짧게 칠 수 있다.

**낱말로 친 것은 건드리지 않는다.** 띄어쓰기가 있거나 요청하는 말투가 섞였을 때만
문장으로 다룬다. 그러지 않으면 멀쩡하던 검색이 틀어진다.

블렌더 없이 확인할 수 있다.

```bash
python3 blender_guide/nl.py
```

### 기능이 아닌 것까지 — 카탈로그 667개

블렌더에는 **기능(오퍼레이터)이 아닌 것**이 많다. 모디파이어는 `모디파이어 붙이기` 라는
기능 하나의 선택지일 뿐이라, 74가지 종류가 이름조차 없었다. 노드는 469가지가
`노드 추가` 하나 뒤에 숨어 있었다. 다 합쳐 **667가지**를 못 찾았다.

| | 개수 |
|---|---|
| 지오메트리 노드 | 245 |
| 셰이더 노드 | 100 |
| 컴포지터 노드 | 88 |
| 모디파이어 | 74 |
| 3D 화면 도구 | 64 |
| 텍스처 노드 | 36 |
| 스컬프트 브러시 | 31 |
| 제약 | 29 |

**한국어와 영어를 함께 보여 준다.** 한국어 이름은 블렌더에 딸려 오는 번역을 그대로 쓴다.
667개 중 601개에 번역이 있었다. 블렌더를 한국어로 쓰는 사람이 화면에서 보는 말과 같아야
헷갈리지 않기 때문이다. 번역이 없는 75개는 손으로 적었다.

**누를 수 있는 단추는 두지 않는다.** 이것들은 실행하는 기능이 아니라 어디에 가서
골라야 하는 것이라, 어디에 있는지 알려 주는 것까지가 할 일이다.

**정리된 항목과 섞지 않는다.** 667개가 같은 자격으로 끼어들면, 하나의 답을 주던 검색이
수십 개를 쏟아낸다. 그래서 정리된 항목에서 못 찾았을 때만 따로 보여 준다. 점검이 이것을
지킨다. `면 나누기` 를 쳤을 때 카탈로그가 섞이면 실패로 잡는다.

### 오타와 소리대로 적은 말 — 비슷한 것 찾기

정확히 못 찾으면 **글자가 닮은 것**을 보여 준다. 글자를 두세 자씩 잘라 조각으로 만들고,
그 조각이 얼마나 겹치는지로 가까움을 잰다. `모서라` 와 `모서리` 는 `모서` 를 함께 갖는다.

```
'키프래임'  → 움직임 기록하기 (가까움 0.18)
'bevle'    → 모서리 둥글게 깎기 (가까움 0.165)
'서브디비전' → 면 잘게 나누기 (가까움 0.374)
```

**정확히 찾은 것이 있으면 끼어들지 않는다.** 유사도는 틀려도 그럴듯해 보여서,
정확한 답 위에 놓으면 오히려 헷갈린다. `물체를 움직이게` 는 지금 검색이 맞히고
유사도는 틀린다. 그래서 아무것도 못 찾았을 때만 나선다.

**문턱은 재어서 정했다.** 뜻 없는 `asdfgh` 가 0.085 까지 올라오고 제대로 된 오타인
`키프래임` 이 0.143, `bevle` 이 0.165 이다. 그 사이인 **0.12** 에 둔다. 더 내리면
아무 말에나 뭔가가 나오고, 더 올리면 오타를 놓친다. 점검이 양쪽을 다 지킨다.

⚠️ **모델을 쓰지 않는다.** 뜻을 아는 임베딩을 쓰면 더 좋겠지만, 그러려면 수백 MB짜리
모델을 애드온에 넣거나 글자를 칠 때마다 바깥에 물어봐야 한다. 둘 다 할 수 없다.
조각 겹침은 바깥 의존이 하나도 없고 1ms 안에 끝난다. 재어 보니 지금 검색이 놓치는
열 가지 중 여덟 가지를 맞혔다.

⚠️ **외래어를 소리대로 적은 말은 이 방법으로 못 잡는다.** `서브디비전` 과 `Subdivide` 는
조각이 거의 안 겹친다. 그런 것은 항목의 별칭에 적어 두는 편이 맞다. 문턱을 억지로
내려 맞추면 엉뚱한 것까지 함께 올라온다.

블렌더 없이 확인할 수 있다.

```bash
python3 blender_guide/similar.py
```

### 정리되지 않은 기능까지 — 블렌더 전체 색인

정리된 항목에서 못 찾으면 **블렌더에 등록된 기능 2,400여 개를 통째로 훑는다.**
이 색인에는 블렌더가 가진 한국어 번역을 얹어 두어서, 383개는 한국어로도 걸린다.

번역은 블렌더에 딸려 오는 파일을 파이썬 기본 기능으로 직접 읽는다.
`bpy.app.translations` 는 **사용자가 지금 쓰는 언어로만** 번역해서, 영어로 쓰는
사람에게는 영어가 돌아온다. 그렇다고 설정의 언어를 잠깐 바꾸면 저장 설정이 켜져 있을 때
화면 언어가 한국어로 바뀌어 버린다. 파일을 직접 읽으면 설정을 건드리지 않아도 된다.

다만 번역이 전부 있는 것은 아니다. 2,459개 중 406개뿐이고, 애니메이션 쪽은 거의 없다.
`Subdivide` 는 `분할` 로 나오지만 `Insert Keyframe` 은 영어 그대로다.
그래서 중요한 영역은 자동 번역에 맡기지 않고 손으로 정리해서 1층에 넣는다.

### 그래도 못 찾으면 — 에이전트에게 물어보기

규칙으로 아무것도 못 찾았을 때만, **컴퓨터에 이미 깔린 에이전트에게 물어본다.**
기본은 꺼져 있고 설정에서 켜야 한다. 바깥 프로그램을 실행하는 일이기 때문이다.

```
'물건이 자꾸 두 개로 늘어나는데 그거 만드는 기능'
  규칙만으로는 → 얇은 면에 두께 주기 · 기능 이름으로 찾기 · 통계 보기      (엉뚱하다)
  에이전트는   → 복제하기 · 연결된 복제 · 일정 간격으로 여러 개 늘어놓기   (4.7초)
```

**설정의 `물어볼 명령` 은 비워 두면 된다.** `claude` 명령줄 도구를 알아서 찾는다.
찾은 자리는 설정 화면에 그대로 보여 준다.

다른 도구를 쓰거나 자동으로 못 찾을 때만 적으면 된다. `{prompt}` 자리에 질문이 들어간다.

```
claude -p {prompt}
```

셸을 거치지 않고 인자로 곧장 넘기므로, 질문에 따옴표나 기호가 있어도 명령으로 해석되지 않는다.

⚠️ **도구를 찾을 때 `PATH` 만 믿으면 안 된다.** 독이나 파인더로 켠 블렌더는 셸을 거치지
않아서 `PATH` 가 `/usr/bin:/bin:/usr/sbin:/sbin` 뿐이다. 사용자가 도구를 어디에 깔든
거기에는 없다. 그래서 `~/.local/bin` 이나 `/opt/homebrew/bin` 처럼 흔히 깔리는 자리를
직접 뒤진다. 부를 때도 그 자리들을 `PATH` 에 채워 넘긴다. 도구를 찾아내도 그 도구가
기대는 것(`claude` 는 `node`)이 또 없어서 실패하기 때문이다.

답을 기다리는 몇 초 동안 **블렌더는 멈추지 않는다.** 딴 갈래로 보내 두고 타이머가
받아 온다. 그 사이에 팝업은 닫히므로, 답은 사이드바에 나타나고 다음에 팝업을 열 때도 보인다.

에이전트가 지어낸 id 나 설명을 덧붙인 답은 걸러 낸다. 우리가 가진 항목만 화면에 오른다.

## 애니메이션

모델링만 다루던 항목에 애니메이션 14개를 더했다. 초보자가 **아직 용어를 모른다는 전제**로 적었다.

| 이렇게 치면 | 이것이 나온다 |
|---|---|
| `물체를 움직이게 하고 싶어` | 움직임 기록하기 (키프레임) |
| `움직임이 뚝뚝 끊겨` | 보간 방식 바꾸기 |
| `표정을 만들고 싶어` | 셰이프키 |
| `카메라가 물체를 따라가게 하고 싶어` | 제약 (Track To) |
| `캐릭터에 뼈대를 넣으려면` | 뼈대 넣기 |

주의할 점도 함께 적었다. 재생해도 안 움직이면 키프레임이 두 개 이상 있어야 한다는 것,
뼈대에 물체를 매달 때는 고르는 순서가 중요하다는 것 같은 것들이다.

## 검색 기록

**골라 본 항목은 저절로 기억된다.** 별표를 누를 필요가 없다.

- 검색어가 없을 때 **최근에 본 것** 다섯 개가 맨 위에 나온다. 두 번 넘게 고른 것은
  `3번` 처럼 횟수가 함께 보인다.
- 검색할 때는 기억해 둔 항목이 **위로 올라온다.**

즐겨찾기와 나눠 둔 까닭이 있다. 즐겨찾기는 사용자가 일부러 남기는 것이고, 기록은
쓰다 보면 저절로 쌓이는 것이다. 초보자는 무엇을 즐겨찾기할지 판단할 만큼 알지 못하므로,
저절로 쌓이는 쪽이 먼저 도움이 된다.

**기록은 검색을 흐리지 않는다.** 얹어 주는 점수를 80점으로 묶어 두었다.
검색 점수는 단계마다 100씩 벌어져 있어서(이름이 똑같으면 1000, 이름으로 시작하면 800),
80점으로는 같은 단계 안에서만 순서가 바뀐다. 그리고 **검색어에 걸리지 않은 항목은
아무리 여러 번 골랐어도 결과에 끼어들지 않는다.** 이 두 가지를 점검으로 지킨다.

설정 화면에서 끄거나, 기억할 개수를 바꾸거나, 쌓인 기록을 지울 수 있다.

## 항목을 직접 더하기

**기본 항목 파일을 고치지 말고 팩을 만든다.** 기본 파일은 애드온을 새 판으로 바꿀 때 덮이기 때문이다.

1. 아무 폴더나 만든다. 예를 들어 `~/blender_guide_packs/`.
2. 애드온 설정 화면의 **추가 항목 폴더** 에 그 폴더를 잡는다.
3. 그 안에 `.json` 파일을 둔다. 폴더 안의 모든 `.json` 을 읽어서 기본 항목에 더한다.

```json
{
  "schema_version": 1,
  "entries": [
    {
      "id": "my_subdivide",
      "ko": "면 잘게 나누기",
      "aliases": ["세분화", "쪼개기", "잘게", "면 나누기"],
      "en": "Subdivide",
      "op": "mesh.subdivide",
      "modes": ["EDIT_MESH"],
      "where": "면 위에서 우클릭 > Subdivide",
      "shortcut": null,
      "note": "실행한 뒤 왼쪽 아래 패널을 펴서 나누는 횟수를 바꿉니다.",
      "tags": ["메시편집"]
    }
  ]
}
```

- **`aliases` 가 검색 품질을 좌우한다.** 자기가 그 기능을 뭐라고 부르는지 떠오르는 대로 넣는다.
  실수로 겪은 증상("까맣게", "안 골라져")을 넣어 두는 것이 특히 쓸모 있다.
- `op` 에 기능 식별자를 적으면 두 가지가 자동으로 따라온다.
  **단축키를 블렌더에서 직접 읽어 오고**, **지금 쓸 수 있는지를 블렌더에게 물어본다.**
  그래서 `shortcut` 과 `modes` 는 `op` 를 적을 수 없는 항목에만 필요한 예비 값이다.
- **기본 항목과 같은 `id` 를 쓰면 그 항목을 덮어쓴다.** 기본 설명이 마음에 안 들면 이렇게 바꾼다.
- 고친 뒤에는 설정 화면의 **항목 다시 읽기** 를 누른다. 블렌더를 껐다 켜지 않아도 된다.

프로젝트마다 다른 항목(그 프로젝트의 폴더 규칙이나 정해 둔 수치)을 그 저장소에 두고
팩 폴더로 잡아 쓰는 것도 같은 방식이다.

## 점검

### 검색이 잘 걸리는지 (블렌더 없이, 1초)

```bash
python3 blender_guide/search.py
```

검색어와 기대하는 결과를 짝지어 둔 시험 25건을 돌린다.
항목을 고친 뒤 이것부터 돌리면 블렌더를 켜지 않고도 검색이 망가졌는지 알 수 있다.

### 문장으로도 찾는지 (블렌더 없이, 1초)

```bash
python3 blender_guide/nl.py
python3 blender_guide/similar.py
```

사용자가 칠 법한 문장 12건을 돌린다. 군더더기를 걷어내는 규칙을 고친 뒤 이것부터 돌린다.

### 애드온이 제대로 붙는지 (블렌더 필요)

```bash
BL=/Applications/Blender.app/Contents/MacOS/Blender

$BL --background --python test_headless.py      # 등록·항목·상황 판단
$BL --background --python probe/check_api.py    # 기대는 블렌더 성질이 그대로인지
GUIDE_PACK_DIR=<팩 폴더> $BL --background --python probe/check_packs.py
```

종료 코드가 0이면 깨끗하다.
`test_headless.py` 는 **`op` 에 적은 기능이 이 블렌더 판에 실제로 있는지도 검사한다.**

### 안내 기능이 도는지 (창이 필요하다)

```bash
$BL --factory-startup --python probe/check_focus.py

# 에이전트에게 실제로 물어본다. ⚠️ 바깥 프로그램을 실행한다.
$BL --python probe/check_agent.py

# 팝업 첫 클릭이 닿는지. 조건마다 따로 띄워야 한다.
for c in none plain focus; do
  GUIDE_CLICK_CASE=$c $BL --factory-startup --enable-event-simulate \
      --python probe/check_click.py
done
```

그리기 손잡이 · 강조 오버레이 · 모드 바꾸기 · 팝업 그리기를 모두 확인한다.
창 없이 띄운 블렌더에는 gpu 문맥이 없어서 `test_headless.py` 로는 이 가운데 하나도
확인할 수 없다. `GUIDE_FOCUS_SHOT=1` 을 앞에 붙이면 강조 표시를 찍은 화면도 `probe/` 에 남는다.

## 만들면서 확인한 것

블렌더 5.1.2 에서 직접 재어 본 값들이다. 판이 올라가면 달라질 수 있으므로,
`probe/check_api.py` 를 돌리면 기대는 성질이 그대로인지 확인할 수 있다.

- 레거시 `bl_info` 방식 애드온이 5.1 에서도 그대로 등록된다.
- 팝업 안에서 **버튼(오퍼레이터)을 누르면 팝업이 닫히고, 속성(프로퍼티)은 닫히지 않는다.**
  그래서 즐겨찾기와 펼치기는 버튼이 아니라 속성으로 만들었다. 이것이 `popup.py` 구조를 정했다.
- `UILayout.activate_init` 이 있어서 팝업이 뜨자마자 검색창에 커서를 넣을 수 있다.
- 블렌더에 등록된 기능은 2,461개이다. 이것이 영어 예비 검색의 재료이다.
- ⚠️ **`bpy.props` 로 프로퍼티를 정의하는 파일에 `from __future__ import annotations` 를 쓰면 안 된다.**
  어노테이션이 글자로 미뤄지는데, 블렌더가 그것을 나중에 모듈 바깥에서 평가해서
  `update` 로 건넨 함수 이름을 찾지 못한다. 팩 폴더를 바꿔도 아무 일이 안 일어나는 증상으로 나타났다.

- ⚠️ **`invoke_popup` 팝업은 단추를 눌러도 닫히지 않는다.** 마우스를 움직이지 않고 같은 자리를
  두 번 누르면 단추가 두 번 눌리는 것으로 확인했다. 그래서 돌리기처럼 마우스를 끄는 기능을
  팝업에서 실행하면, 변형은 시작되지만 팝업이 그 위를 덮은 채로 남는다. 점선 안내선은
  기준점에서 마우스까지 그어지는데 마우스가 팝업 위에 있으니 가려지고, 팝업이 키 입력을 먼저
  가져가므로 `X` · `Y` · `Z` 축 고정도 안 먹는다.
  **팝업을 닫는 API 는 블렌더에 없다.** `bpy.ops` 전체를 훑어도 없다. 다만 팝업은 마우스가
  밖으로 나가면 스스로 닫히므로, `Window.cursor_warp` 로 커서를 팝업 밖으로 내보내서 닫는다.
  `runner.py` 가 그 일을 한다. `probe/check_click.py` 의 `close` 조건이 이것을 지킨다.
  참고로 팝업 레이아웃의 기본 `operator_context` 는 재어 보니 이미 `INVOKE_REGION_WIN` 이라서,
  그것을 손대는 것은 원인과 무관했다.

- **블렌더의 절반은 기능이 아니다.** `bpy.ops` 를 다 훑어도 모디파이어 74가지,
  노드 469가지, 브러시 31가지, 도구 64가지는 한 줄도 안 나온다. 종류를 고르는
  선택지일 뿐이기 때문이다. 이것들은 각각 다른 자리에서 따로 뽑아야 한다.
- **블렌더 번역은 대체로 음차이다.** `Mesh Cache` 가 `메시 캐시`, `Blackbody` 가
  `블렉보디` 로 나온다. 그래도 그대로 쓴다. 블렌더를 한국어로 쓰는 사람이 화면에서
  보는 말과 달라지면 오히려 못 찾기 때문이다. 영어를 함께 보여 주는 것으로 메운다.
- **유사도는 무게를 곱한 뒤에 길이를 재야 한다.** 순서를 바꾸면 가까움이 1을 넘는다.
  실제로 6.2 가 나왔고, 그러면 문턱이 아무 뜻이 없어진다. 점검이 이것을 지킨다.
- **너무 넓은 별칭 하나가 문장 검색을 가로챈다.** `새 물체 만들기` 에 `add` 라는 별칭이
  있어서, `how to add a loop cut` 이 그리로 갔다. 별칭이 정확히 맞으면 900점인데
  영어 이름이 맞는 것은 450점이라 이길 수가 없다. 영어 이름은 `en` 이 이미 담고 있으므로
  흔한 영어 동사를 별칭으로 두면 안 된다.
- ⚠️ **독으로 켠 블렌더는 `PATH` 가 거의 비어 있다.** 터미널에서 켜면 도구를 찾고
  독으로 켜면 못 찾는 일이 실제로 벌어졌다. 찾을 때도 부를 때도 흔한 자리를 채워 줘야 한다.
  찾아내는 것과 돌리는 것은 별개다. 자리를 찾고도 `node` 가 없어서 코드 1 로 끝났다.
- ⚠️ **바깥 프로그램을 부를 때 `stdin` 을 반드시 막아야 한다.** 막지 않으면 부른
  프로그램이 블렌더의 입력을 물려받아 무언가 들어오기를 기다린다. `claude` 는 3초를
  기다린 뒤 경고를 내고 진행하는데, 그 사이에 답이 비어서 돌아오는 것을 겪었다.
  `stdin=subprocess.DEVNULL` 로 막으면 답도 제대로 오고 3초도 아낀다.
- **흔한 낱말 하나가 정확한 낱말을 이긴다.** 문장 검색에서 `면을 둘로 나누고 싶어` 가
  `면 밀어내기` 로 갔다. `면` 하나만 걸린 항목이 `면` 과 `나누` 를 둘 다 맞힌 항목을
  점수에서 이겼기 때문이다. 지금은 걸린 낱말이 많을수록 올려 준다.
- ⚠️ **한글 입력 중에는 글자 글쇠를 단축키로 쓸 수 없다.** 입력기가 글쇠를 자모로 바꿔
  넘기는데 블렌더에는 자모에 해당하는 글쇠가 없어서, 종류가 빈 사건이 된다.
  수식키를 바꾸는 것으로는 해결되지 않는다. `Ctrl` 을 `Cmd` 로 바꿔도 마찬가지였다.
  기호 글쇠로 된 단축키를 하나 더 두어야 한다. 이것은 블렌더가 받는 사건을 직접 기록해서
  알아냈다. 짐작으로는 세 번을 헛짚었다.
- **macOS 가 먼저 가로채는 조합이 있다.** `Cmd`+`Shift`+`/`(도움말), `Cmd`+`Shift`+`4`
  (화면 찍기), ``Cmd``+`Shift`+`` ` ``(창 넘기기) 는 블렌더까지 오지도 않았다.
  기록에 아무 사건도 안 남는 것으로 구별할 수 있다.

### 화면에서 눈으로 보고 잡은 흠 셋

숫자로는 통과했는데 실제로 띄워 보고서야 드러난 것들이다.

- **`poll()` 만 믿으면 안 된다.** `하나를 여러 물체로 쪼개기`(`mesh.separate`)는 에디트 모드
  전용인데 오브젝트 모드에서도 `poll()` 이 참을 돌려주어서, 오브젝트 모드 추천 목록에 끼어들었다.
  지금은 사람이 적어 둔 `modes` 를 최소 조건으로 먼저 보고, 통과한 것만 `poll()` 로 더 따진다.
- **한 기능에 단축키가 여럿 걸려 있다.** `선택한 것을 화면 가운데로` 가 `Numpad .` 대신
  `Cmd+Numpad .` 로 나왔다. 지금은 같은 키맵 안에서 **수식키가 적은 쪽**을 고른다.
- ⚠️ **검색창에 커서가 들어가 있으면 팝업 안의 첫 클릭이 삼켜진다.** 설정의 `팝업을 열면 바로
  칠 수 있게 한다`(`activate_init`)를 켜면 검색창이 글자 입력 상태로 남는데, 그 상태에서
  팝업 안을 처음 누르면 그 클릭이 입력 상태를 빠져나오는 데 쓰이고 단추까지 닿지 않는다.
  사용자는 눌렀는데 아무 일도 안 일어난 것처럼 느낀다. 이벤트를 흉내 내어 세 조건을 재어
  확인했다. 검색창이 없을 때와 커서가 없을 때는 첫 클릭에 눌리고, 커서가 들어가 있을 때만
  삼켜진다. 열자마자 Enter 를 눌러 입력을 끝내면 첫 클릭에 눌린다.
  `probe/check_click.py` 가 이 사실이 그대로인지 지켜본다.
- **실행 단추는 끝내 고치지 못해 걷어냈다.** `돌리기` 를 `지금 실행` 으로 부르면 3D 화면에서
  R 을 누른 것과 달랐다. 점선 안내선이 없고 축 고정도 안 됐다. 원인은 팝업이 닫히지 않는
  것이었는데, 닫는 API 가 없어서 손쓸 방법이 없었다. 다음 세 가지를 시도했고 모두 듣지 않았다.
  `operator_context` 바로잡기(팝업 기본값이 이미 그 값이었다), 타이머로 미뤄서 부르기(팝업이
  닫히지 않으니 소용없다), `cursor_warp` 로 커서를 내보내 닫기(흉내 낸 시험에서는 통했지만
  실제 사용에서는 증상이 그대로였다). 그래서 기능을 대신 실행하지 않기로 했다.
- **자동 조회가 늘 더 나은 것은 아니다.** `시점 돌리기` 의 자동 조회 값은 `Mouse/Trackpad Rotate`
  였는데, 이것으로는 무엇을 눌러야 하는지 알 수 없다. 그래서 항목에 `prefer_manual` 을 켜면
  손으로 적은 값을 앞세우도록 했다. 마우스를 끄는 조작에만 쓴다.
